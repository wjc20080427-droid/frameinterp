# mac-frame-interp

采集卡实时补帧（macOS 26+，Apple Silicon）：ShadowCast 3 采 1080p60 → 去掉重复帧 → Apple 低延迟补帧 → 均匀 60fps 显示，音频独立直通。

## 编译 / 运行

```bash
swift build -c release
.build/release/FrameInterp --list                 # 列设备和格式
.build/release/FrameInterp                        # 自动选采集卡，全屏
.build/release/FrameInterp --ires 720             # 补帧在 720p 上做（M2 上 < 12ms），真实帧仍是 1080p
.build/release/FrameInterp --test --windowed      # 不接采集卡：内置测试图案
.build/release/FrameInterp --selftest --seconds 20  # 无窗口，只测管线和补帧耗时
```

首次运行系统会弹摄像头 / 麦克风权限，请允许给终端。快捷键：空格 补帧开关，f 全屏，q 退出。

## 管线

```
AVCaptureSession（1080p60，非 MJPEG 优先，输出 420v）
  → DupDetector：每 8 像素抽样亮度，和"上一个唯一帧"比较
       平均差 >= --thr(0.5) 或 变化点(>12) 占比 >= --pct(0.05%) → 新帧（混合判定）
  → 唯一帧用 VTPixelTransferSession 拷进自己的 CVPixelBufferPool（BT.709 附件）
  → 平均差 > --cut(40) → 切场景，不补帧
  → VTLowLatencyFrameInterpolation（N-1, N, phase 0.5）
  → 显示队列（限长 --queue 4，超了丢最旧）：先中间帧，下一个刷新周期再显示 N
  → NSView.displayLink 每个刷新周期取一帧 → AVSampleBufferDisplayLayer（DisplayImmediately）
音频：独立 AVCaptureSession + AVCaptureAudioPreviewOutput（只配对采集卡自己的音频设备，不会用麦克风代替）
```

## 统计（每秒一行）

采集 / 唯一 / 显示帧率，补帧次数和平均 / 最大耗时，失败，切场景，队列丢帧，空拍（补帧开着但这个刷新周期没有新帧可显示），
重复帧平均差（括号里是最大平均差 / 最大变化点占比，用来调 --thr / --pct），唯一帧平均差，延迟（唯一帧到达 → 送进显示层）。
退出时打印汇总（中位 / 95% / 99% / 最大补帧耗时）。

## 在 M2 上实测到的 VT 限制

- `supportedPixelFormats` 只有 `420v`。属性字典里写的 `x420` 和 BGRA 都会报 -19740。
- 1080p 补帧：连续送帧约 15ms；按 30fps 节奏送约 20ms（帧之间 GPU 会降频）。720p 约 10.5ms。
- 空间 2× 模式（`spatialScaleFactor: 2`）报 -19730 "Processor is not initialized"，所以没有用。

## 补帧节奏（2026-11-13 按 iPad 实测改）

- 按两个新画面之间的实际间隔决定补几帧：间隔跨几个刷新周期就一共显示几帧（17ms 不补、33ms 补 1 帧）。
  每段最多补 1 帧，补不够的记"欠账"，下一次短间隔时多补一帧还上，平均每个刷新周期正好一帧。
  补 2 帧（1/3、2/3）在 M2 上 720p 要 33ms、1080p 要 91ms，比一个刷新周期还长，实测反而更卡，所以关掉了。
- 重复帧阈值自动适应噪声：最近 2 秒所有帧差值的第 20 百分位当噪声，判断线 = max(基准, 3 × 噪声)，上限平均差 1.5、变化点 0.2%。
  （第一版"把判成重复的帧当噪声、判断线 = 1.5 × 噪声"会自己越抬越高：采集卡 12 分钟里 95% 的秒数没有新画面，已改掉。）
- 只有差值明显分成两堆（第 20 百分位 < 第 80 百分位的 1/4，即 30 帧游戏那种）时才用这个噪声；60 帧游戏、静止画面不抬高判断线（地平线 4 实测：不加这条，60 帧画面的小幅运动被当噪声，新画面掉到每秒 10~35）。
- 保险：连续 3 帧判成重复但仍有些差别（超过判断线 30%）就强制当新画面，画面不会卡住。

## 画面增强（锐化 + 放大）

- RCAS 锐化（AMD FidelityFX，FSR 1 的锐化部分）+ 可选 MetalFX 空间放大，补帧之后、显示之前做，真实帧和补出来的帧都过。
- M2 实测（全屏，同时补帧）：只锐化每帧 1.8ms；MetalFX 放大到 2940×1654 每帧 6ms，延迟多约一帧（49 → 80ms）。
  所以默认：锐化"锐利"开，MetalFX 放大关（由系统显示层放大）。
- Apple 的 AI 超分（VTLowLatencySuperResolutionScaler）输入最大 1280 宽，1080p 用不了；VTSuperResolutionScaler 是离线用的，太重。

## 录制 3 秒画面（逐帧检查）—— 2026-11-19 已删除

- 设置栏「显示」里的按钮或快捷键 r：把接下来 3 秒屏幕上实际显示的每一帧录成 ProRes（~/Movies/FrameInterp/录制-时间.mov），旁边 .txt 标明每帧是真实帧还是补帧、时间点。
- 平时不占资源；录制时显示不受影响（实测 3 秒录 181 帧，显示仍 58~60 帧/秒）。

## 界面保护（照搬 Windows 版 UiProtect / UiLayer）

- 五块区域（GTA 6 演示估的位置）：左上血量、右上武器/通缉、左下小地图、右下赛事/计时、中间准星；边缘渐变。
- 左上 / 左下 / 右下自动识别：每个真实帧逐像素和上一帧比，没变 +1（最多 20）、变了 -3，连续 6 帧没变算界面，向外膨胀 12 像素；右上和准星整块保护。
- 只处理补出来的帧，在 420v 上直接做。只在识别区域里算：每个真实帧约 0.6ms，每个补帧约 0.6ms。

## 补帧延迟优化（2026-11-14）

测法：测试图案在画面正中（准星保护区，补出来的帧里也是真实帧内容）写内容帧号，录自己的窗口读出"新内容第一次上屏"的时间（FI_LATTEST=1 FI_STAMP=content FI_STAMPPOS=center）。每种设置跑 3 次取平均。

| 第一反应延迟 | 优化前 | 补帧直接上屏 | + 关键路径精简 |
|---|---|---|---|
| 原分辨率 | 54.6ms | 51.9ms | 49.5ms |
| 720p | 39.7ms | 36.4ms | 28.8ms |

- 补帧直接上屏：中间帧算完马上交给显示层，跳过一次刷新回调，真实帧在下一次刷新显示。
- 关键路径精简：720p 时先只拷补帧用的小图就开始补帧；原分辨率那份在补帧开始后再拷；界面识别放到另一条队列和补帧同时跑。
- 削积压：队列连续 0.5 秒没清空就丢一帧（优先补帧），避免延迟永久多一两帧。

## 补帧档位（2026-11-14）

| 档位 | 补帧分辨率 | 只锐化补帧 | 排队 | 第一反应延迟（实测 3 次平均） |
|---|---|---|---|---|
| 低延迟 | 540p | 关 | 4 | 约 31ms |
| 平衡 | 720p | 柔和 | 4 | 约 35ms |
| 质量（默认） | 原分辨率 | 关 | 4 | 约 49ms |

- 排队 3 帧只比 4 帧省约 1ms，却会丢帧，所以三档都用 4。
- "只锐化补帧"：720p 补出来的帧偏软，单独锐化；真实帧不动（全局锐化会让画面显得暗）。每个补帧约 1.5ms。
- 三项（补帧分辨率、补帧锐化、延迟和流畅）在高级选项里，改过任何一项档位显示"自定义"。

## 开补帧时画面闪（2026-11-14 已修）

采集卡的帧带 CGColorSpace 附件（拷贝时跟过来），补出来的帧没有；显示层对两种帧颜色解释不同，窗口整体亮度每帧 76 ↔ 83 来回跳。
现在每个显示的帧都先清掉全部附件、只设 BT.709 三项。修后录用户窗口 3 秒：相邻帧亮度差平均 0.35（修前 5.49），一高一低来回跳 1 次 / 155（修前 115 / 153）。

## 窗口模式还在闪（2026-11-14 已修）

- 真实帧和补出来的帧来自不同缓冲池，每行字节数 2884 / 2904 不同，按缓冲生成的格式描述每帧都"变了"（每秒 60 次），显示层每帧重新配置。现在格式描述只按"像素格式 + 尺寸"建。
- 补出来的帧是 720p / 540p 时先放大回原分辨率再显示（不然尺寸每帧变）。
- 静止直通在补帧开着时也用 420v 拷贝，不再和 4:2:2 来回切。
- 平衡档只锐化亮度，输出仍是 420v。
- 界面保护：所有区域都只保护识别出的静止像素，不再整块盖住；默认关。
- 修后测试图案三个档位格式变化都是 0 次/秒。

## 补帧档位（2026-11-14 第二版，按用户实测意见改）

540p 低延迟档删掉：动起来真实帧 1080p、补帧 540p，一帧清晰一帧糊，锐化救不回来。

| 档位 | 设置 | 第一反应延迟（3 次平均） |
|---|---|---|
| 低延迟 | 720p 补帧，不锐化 | 约 35ms |
| 平衡（默认） | 原分辨率补帧，不锐化 | 约 48ms |
| 质量 | 原分辨率 + 所有帧轻度锐化（亮度，柔和） | 约 45ms（锐化每帧约 1ms，差别在测量误差内） |

质量档用锐化而不是 MetalFX：MetalFX 全屏每帧 6~7ms、延迟多约 30ms，还会和补帧抢 GPU；锐化只在亮度上做，每帧约 1ms。三档格式变化都是 0 次/秒，60 帧不丢帧。

## 帧数和延迟浮窗（2026-11-14）

设置栏「显示」→「帧数和延迟」（⌘I，默认关）：画面左上角一条毛玻璃浮窗，一行显示 帧数 · 延迟，每秒刷新。
浮窗是窗口里的独立视图（NSVisualEffectView），不进视频帧：不会被补帧、锐化，也不会被「录制 3 秒」录进去。
帧数 = 屏幕每秒实际显示的帧数（开补帧时含补出来的帧）。延迟 = 采集时间戳 → 送进显示层的平均值，不含采集卡本身和屏幕刷新（约再多 10~20ms）。
曾试过 CPU / GPU / 内存：补帧几乎不涨 GPU（看起来跑在神经网络引擎上，GPU 占用不统计它），用户决定不要。

## 界面保护第二版（2026-11-14）：整个画面自动识别

先测了 Apple 补帧会不会自己处理固定界面：不会。合成测试（彩色图形背景平移 + 固定的血条 / 文字 / 小地图 / 准星 / 字幕），
背景每对帧平移 24px 时界面像素 19% 明显错（字重影、叠成两份），48px 时 24%；没有界面时背景误差只有 0.5。

新做法（不再用按 GTA 估的五块区域）：一个像素算界面要同时满足 ① 连续 8 个以上真实帧没变 ② 有清楚边缘（Sobel）
③ 周围 ~96 像素里有块在动 ④ 整个画面 25% 以上的块在动（镜头在转）。符合的向外扩 12 像素盖住重影，保护程度每帧最多降 0.25（不闪）。
识别在半分辨率上做。

| 场景 | 原补帧 界面明显错 | 保护后 | 其它 |
|---|---|---|---|
| 界面 + 平移 24px | 19.3% | 0.5% | 背景误差 0.74 → 0.80 |
| 界面 + 平移 48px | 23.6% | 1.4% | |
| 界面 + 平移 96px | 24.5% | 5.0% | 重影偏移超过 12px 扩展范围 |
| 无界面 + 平移 48px | — | — | 背景误差 0.47 → 0.48（几乎不保护） |
| 镜头不动 + 物体移动 | — | — | 物体误差 0.9 → 0.9（没有条件 ④ 时 6.9：物体被擦掉一部分） |

耗时：识别每个真实帧 ~1.9ms（另一条队列，和补帧同时做，不在延迟路径上）；合成每个补帧 ~0.7ms。
日志每秒一行"界面保护：画面在动的块 x%"。默认开（用户 2026-11-14 决定），在高级选项里可关；"显示保护区域"把保护的地方染洋红色。

## 界面保护已删除（2026-11-14）

用户实际游戏里试了第二版，觉得效果不好，要求整个删掉：UiProtector.swift、设置开关（界面保护 / 显示保护区域）、日志行都已移除。
补出来的帧现在只做必要的放大（720p → 原分辨率），直接显示。上面两节界面保护的记录只作历史参考。

## 发布（2026-11-14，v1.0）

`./make-release.sh` → `dist/FrameInterp-1.0.dmg`（App + "应用程序"快捷方式 + release/安装说明.txt）。
没有 Apple 开发者证书，只能本机临时签名（ad-hoc）：别人第一次打开要去 系统设置 → 隐私与安全性 → "仍要打开"。有 Developer ID 后可加签名 + 公证。

采集卡识别不再只认 Genki：外接视频设备按"像不像采集卡"打分（常见品牌 / 型号名 +100，能出 1080p60 +40，名字像网络摄像头 −80），
只有一个外接设备时直接用；虚拟摄像头（OBS、Camo、Zoom…）不列出。
声音配对：名字相同 / 互相包含；否则看 USB 声卡 ID "AppleUSBAudioEngine:厂商:产品名:…" 里的产品名（便宜采集卡视频叫 USB Video、声音叫 USB Digital Audio 也能配上）。
只在 ShadowCast 3 上实测过；其他卡按名字和格式推断。

## 快速转镜头时掉到 48 帧（2026-11-14 已修）

用户实玩日志：18:28:09 那一秒唯一帧平均差 31.5，有 12 帧平均差超过 40 被当成"切场景"不补帧，显示只有 48 帧（另有 50、53 的几秒）。
改为：平均差超过阈值 **而且** ≥ 最近几帧滑动平均的 2.5 倍才算切场景（真切场景是突然一下）。测试图案的整屏切换仍能识别（几秒 1 次），其余秒 60 帧。


## 2K / 4K 和新界面（2026-11-18，v1.1）

- 实测 VTLowLatencyFrameInterpolation 只接受 1920×1080、1280×720；2560×1440、3840×2160、1600×900、960×540 都报 -19730。
  2K / 4K 输入补帧时缩到 1080p（选 720p 就 720p）。`hiResUnified`（默认）：补帧时真实帧也按 1080p 显示，观感一致；否则真实帧原生、补帧放大。
- ShadowCast 3 支持 2560×1440 420v@60/120、3840×2160 420v@60（4:2:2 yuvs 在 2K 只有 50、4K 只有 25）。
- 测试图案 `FI_TESTRES=1440 / 2160`。4K：显示 60、补帧 ~20ms、缩小拷贝 ~6ms、延迟 ~43ms；4K 关补帧直通 0.2ms。
- 界面：顶栏 + 画面 + 底部工具栏 + 设置面板（2026-11-21 起改成自己的设计：来源卡片首页、居中的底部坞）；红绿灯自己画（系统标题栏挪不进 52 点顶栏）。

- 2026-11-19：删掉录制 3 秒；全屏时鼠标 5 秒不动 `NSCursor.setHiddenUntilMouseMoves`（设置可关，键 hidecur）。

## 串流窗口输入的全屏（2026-11-19）

问题：串流软件窗口被系统全屏（另一个桌面）或完全不透明的窗口盖住时，系统把它判为不可见（occlusionState 没有 .visible），串流软件省电降帧。
实测（.build/tools/occ 实验）：不透明盖住 / 透明背景但内容不透明 / 系统全屏 / 留 1 像素缝 → 都判不可见；盖它的窗口 alphaValue 0.995 → 仍判可见。
做法：输入是窗口时 alphaValue = 0.995；全屏改为当前桌面铺满（FIWindow 允许盖住菜单栏位置，presentationOptions 自动隐藏菜单栏 / 程序坞）。
验证：替身"串流窗口"被完全盖住 25 秒，一直判可见、每秒 60 帧；FrameInterp 采集它稳定 57 帧。
