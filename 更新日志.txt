2.5.3（2026-11-25）
==================================================
· 改进：720p 补帧时（M1 系列、macOS 26、1080p 太慢自动降级），补出来的 720p 帧直接由清晰放大一次放大到屏幕，
  不再先用系统转换拉到 1080p 再放大一次，少一次插值，补出来的帧没那么软。输出尺寸和真实帧始终一样（不会闪）。
  M2 实测：补帧 11ms、放大 1.8ms、延迟约 31ms、稳定 60 帧。
· 改进：字幕保护改在显卡放大时合成（720p 补帧时）：真实帧按自己显示时完全一样的方式放大，位置图里要保护的像素
  换成它的结果。有字幕 / 提示时补出来的帧也只放大一次，保护区和真实帧显示的一模一样；不用再在 CPU 上逐像素替换。
  1080p 补帧时补出来的帧和真实帧一样大，照旧在 CPU 上合成（本来就不多放大）。日志统计里多了"显卡字幕 N"。
  M2 实测（测试图案，720p 补帧 + 字幕保护）：放大 2.3ms、延迟约 35～38ms、稳定 60 帧。
· 改进：记住"这台 Mac 上 1080p 补帧太慢"（按芯片、型号、系统版本记，升级系统会重新测）。
  普通补帧（30 → 60）就跟不上的，下次一开始就用 720p，不用再等 3 秒；只是 120Hz 屏幕上 60 → 120 跟不上的，
  下次看到 60 帧画面马上降，30 帧游戏仍用 1080p。60 → 120 第一次判断也从 3 秒缩短到 1 秒（每帧平均超过 16.5ms 就一定跟不上）。
· 修复：1080p 补帧太慢自动改用 720p 时偶尔闪退（旧补帧器已结束会话，队列里剩下的补帧任务还在调用它）。
· 诊断记录：Apple 低延迟 AI 超分（VTLowLatencySuperResolutionScaler）在 macOS 27 上输入最大仍是 1280，只能 720p→1080p，
  M2 上每帧 2.9ms；但用 GTA 6 截图对比比现在的放大更糊（亮度 PSNR 31.3 dB 对 35.4 dB，树叶栅栏像涂抹），不采用。

2.5.2（2026-11-24）
==================================================
· 修复：分辨率菜单以前只列出能跑满 60 帧的档。有用户的"USB3 Video"采集卡 2K 只有 10/20/30 帧（不压缩 NV12），
  被标成"这个设备不支持"，OBS 却能选。现在采集卡有的档都能选，跑不满所选帧率的标"最高 N 帧"
  （配置向导里标"2K（30 帧）"），选了这种档时下面提示会掉帧、建议换能跑满的档。
  测试钩子 FI_FAKECAPS=1080:60,1440:30（配合 --test）假装采集卡只有这些档。
· 新增：模拟器。首页"窗口"卡片分「串流 / 模拟器」两页，窗口选择器也能切换。认识 15 个 Mac 模拟器
  （Dolphin、PCSX2、DuckStation、PPSSPP、RetroArch、RPCS3、Cemu、Ryujinx、Azahar/Citra、melonDS、shadPS4、Vita3K、xemu、mGBA、OpenEmu），
  窗口标"模拟器 · 主机名"并排在前面；「支持的模拟器」列表写了每个模拟器要改的设置（后台输入 / 失去焦点暂停）。
  连接模拟器窗口时弹出这条提示；说明里按屏幕刷新率写清楚：120Hz 屏幕 60 帧补到 120，60Hz 屏幕 60 帧不补、30 帧补到 60。
  只有 Dolphin 有人用过，其他模拟器的设置项名称未逐个核实。
· 改进：120Hz 屏幕上 60 帧的画面（模拟器、串流）补帧跟不上时（补完不到 1.6 倍）也自动改用 720p 补帧
  （M2 上 1080p 补一帧约 18～20ms，60 → 120 每帧要在 16ms 内补完）。静止画面直通时不误判。
  测试钩子 FI_WINKIND=1（首页打开在模拟器页）、FI_EMULIST=1（打开模拟器列表）。
· 改动：配置向导里 PS5 和 Xbox Series X 的"主机输出"从 1440p 改成 2160p，PS5 Pro 的"4K"也写成 2160p 统一口径（游戏按输出分辨率重建，2160p 细节最多，
  采集 1080p 时正好缩小 2 倍）。

2.5.1（2026-11-23）
==================================================
· 修复：M1 Pro（macOS 27）开 1080p 补帧只有 10 帧（B 站用户反馈）。Apple 论坛有人实测 M1 Pro 低延迟补帧最大 720p，
  Console Link 等软件在 M1 Pro 上也只支持 720p。现在：
  - M1 系列芯片（M1 / Pro / Max / Ultra）一开始就用 720p 补帧（采集分辨率不变），状态里说明原因；
  - 其他芯片如果 1080p 补帧跟不上（每帧超过 28ms，或 30 帧左右的游戏补完显示不到 1.3 倍）连续 3 秒，自动改用 720p 补帧并提示。
  本机用 FI_FAKE_SLOW=1 模拟：3 秒后自动切到 720p，补帧每帧约 10ms、稳定 60 帧；正常情况不会误切。M1 Pro 真机还没验证。

· 修复：别人的 Mac 上补帧报「预热 10 秒仍失败 -19730 Processor is not initialized」，只显示原画面。
  这个错误在 M2 上只在补帧尺寸不被支持时出现过，推测那台 Mac 不支持 1080p 补帧。
  现在 1080p 补帧启动失败会自动改用 720p 补帧再试一次（状态里注明「这台 Mac 上 1080p 补帧不可用，自动用 720p」）；
  两种都失败时，状态里显示补帧尺寸、芯片型号和系统版本，并提示把日志发给作者。启动时日志里也记一行这台 Mac 的芯片、型号、系统版本。
  （本机用 FI_FAIL1080=1 模拟 1080p 失败：自动改 720p 后补帧正常，每帧约 10.5ms。那台 Mac 上 720p 能不能用还没验证。）
  原因查到了：网上多个项目实测，macOS 26.x 上 Apple 低延迟补帧最多处理 1280×720 的像素量（超了不报错、补帧时报 -19730），

2.4（2026-11-20）
==================================================
· 改进：清晰放大在「缩小」时（4K 采集 → 屏幕 2940×1654，约 0.77 倍；或 2K 放进较小的窗口）改用按比例放宽的三次核，横竖各一遍。
  原来的 5 点三次插值只看周围一小圈像素，缩小时细线、小字、栅栏会闪、出摩尔纹。
  4K 测试画面上（和 vImage 高质量缩小比）：小字 38.8 → 41.8dB，细线 43.4 → 47.4dB，2 像素栅格 28.4 → 31.7dB，
  画面平移时的波动（闪烁）栅格 17.8 → 8.5dB、自然画面 3.5 → 1.8dB。
  代价：4K 每帧 GPU 1.5 → 3.7ms；程序里 4K 直通每帧约 5.4ms（含锐化），稳定 60 帧。放大（1080 / 2K）不受影响。
· 改进：压缩传输（MJPEG）时清晰放大的锐化自动减半。锐化会把压缩带来的方块和字边波纹一起放大：
  用 JPEG 模拟（2K / 4K，质量 0.5~0.95），标准锐化比不锐化多 2~3.6dB 的压缩损伤，减半能挽回一半左右。
  也试了 8×8 去方块滤波：各种质量下都更差（这种码率下方块本来就很轻，滤波抹掉的是真细节），没采用。
· 改进：画面设置（PICTURE）写得更详细，加了三个选项（都默认开）：「2K / 4K 自动轻度锐化」「缩小防闪烁」「压缩传输时减弱锐化」。
  每档锐化都写明强度（0.25 / 0.5 / 0.75 / 1.0）和适用场景；下面实时显示当前怎么处理的，
  比如「2560×1440 → 2940×1654，放大 1.15 倍 · 三次插值 · 锐化 0.25（2K/4K 自动）· 每帧 3.2ms」。
· 缩小防闪烁只在缩到 0.85 倍以下时启用（2K 放进稍小的窗口这种只缩一点的情况几乎不闪，省时间）。
· 改进：串流窗口按窗口画面的原始像素采集（Retina 上 1 点 = 2 像素，1920×1080 ~ 3840×2160），不再先被系统缩到 1920×1080。
  不补帧时从原始像素一步缩放到屏幕（少一次缩放）；补帧时和 2K / 4K 采集卡一样，在补帧器里按面积平均缩到 1080p。
  窗口变大 / 变小 10% 以上会自动按新尺寸重新打开。模拟串流窗口实测：不补帧时小字清晰度（梯度能量）高约 7%，帧率、延迟不变；
  补帧时最终还是 1080p（Apple 补帧的上限），差别不大。设置里加了提示：PS Remote Play 要在 设置 → 视频画质 里选 1080p。
· 改进：窗口列表里也会出现「系统全屏」的窗口（点绿色按钮全屏、单独一个桌面的串流 App），标「（系统全屏）」。
  原来只列当前桌面上看得见的窗口，全屏的串流窗口在另一个桌面，选不到。全屏窗口没有标题栏，不再裁掉顶上 32 点。
  测试：一个全屏的测试窗口在另一个桌面上，按 2912×1638 采集，30 帧补到 60 帧正常。
  用户实测 Chrome 里的 xbox.com/play 系统全屏：切回 FrameInterp 后 Chrome 停止绘制，采集 0 帧。
  现在选了系统全屏的窗口时，FrameInterp 会自动切到它的全屏桌面、铺满盖在它上面（不透明度 0.995，它仍算看得见，不会停）。
  普通程序的窗口进不了别的程序的全屏桌面（实验验证），所以这期间临时切成「辅助程序」，程序坞里不显示图标；换输入或停止后恢复。
  测试窗口验证：FrameInterp 出现在它的全屏桌面最上层，30 帧补到 60 帧正常。真实 Chrome 还要用户再试。
· 新增：主机配置（首页最上面、设置 → 输入 里；第一次用采集卡开补帧时自动弹出）。只选主机：PS5 / PS5 Pro / Xbox Series S / Xbox Series X，
  每台写明 GTA 6 在上面的内部分辨率，和推荐配置及原因，一键应用：
  - PS5：主机输出 1440p，锐化柔和；PS5 Pro：输出 4K（PSSR 的细节只有 4K 输出才拿得到），不锐化；
  - Series X：输出 1440p（菜单里没有就 4K），锐化柔和；Series S：输出 1080p，锐化标准；
  - 四台都是采集 1080p 60 帧不压缩、补帧开（补帧最高 1080p）；都提醒 HDR、VRR 要关。
  应用后保存，首页显示当前配置，换主机时再选一次。
  （中间做过 5 步版：选显示器、主机输出、诊断采集卡；太复杂，诊断还会闪退——选到只支持 120 帧的档位硬设 60 帧，系统抛异常——已删掉。）
· 修复：「补帧锐化」在清晰放大开着时其实不起作用，现在开着清晰放大时这一项改成说明文字。
· 修复：开补帧后 2K / 4K 自动锐化会失效（补帧时送来的帧已经降到 1080p），现在按采集分辨率判断。
· 试过没用上：AMD FSR 1 的 EASU 边缘自适应放大（多 2.6ms，1.5 倍放大时和三次插值看不出差别）；
  Apple 的低延迟超分辨率（输入最大 1280×1280，1080p 进不去）。

2.3（2026-11-20）
==================================================
· 修复：画面一直偏暗。原因是显示时给每帧标的亮度曲线是 BT.709，macOS 按这个标签转换颜色时会把画面压暗，
  暗部最明显。实测同一块灰：标 BT.709 显示成 15 / 65 / 121 / 188，正常（浏览器、Genki 网页直接解码）是 28 / 75 / 128 / 191。
  现在改标 sRGB 曲线（原色和矩阵仍是 BT.709），和直接解码一致。采集卡数据本身没问题：标准范围、不是 HDR。
· 新增：日志里每 5 秒记一次「亮度诊断」（采集卡的颜色标签和亮度分布），方便以后排查颜色问题。
· 新增：「清晰放大」（画面设置第一项，默认开）。原来是系统把 1080p 双线性拉到屏幕大小（全屏 2940×1654），
  字边缘发糊；现在先用 Catmull-Rom 三次插值直接放大到屏幕实际像素，再显示。2K / 4K 信号会自动加一点锐化。
  开着时代替原来的「锐化」。M2 上每帧 GPU 约 1.5ms（2K 加锐化约 2.4ms），实测帧率、补帧延迟和关掉时基本一样。
  （第一版用 Lanczos，每帧要 8ms、补帧延迟多 12ms，已换掉。）
· 新增：输入 → 采集卡里加「压缩传输（MJPEG）」开关（默认关）。打开后优先用采集卡的 MJPEG 格式，由系统解码，
  用来在 5Gb/s 的 USB 上跑 4K 60 帧、2K 120 帧（不压缩的 4K60 要约 6Gb/s）。同一档先试 MJPEG，没画面再退回不压缩。
  采集卡在 macOS 上没有提供 MJPEG 格式时，开关下面会提示「不起作用」。日志里会列出采集卡的全部格式。
